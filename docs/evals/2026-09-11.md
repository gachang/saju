# Luna 실제 API 평가 및 프롬프트 튜닝

## 실행 조건

- OpenAI 공식 `/v1/models/gpt-5.6-luna` 접근 확인: HTTP 200.
- 실제 Responses API: 최초 생성 10회 + 1회 보정 방식 확인 2회 = 총 12회. 자동 API 재시도는 0회.
- 실제 사람의 이름·생일을 사용하지 않고 합성 입력으로 계산한 근거를 전송했다.
- 주 계산 `manseryeok@2.0.0`, 참고 검증 `@fullstackfamily/manseryeok@1.0.8`.
- `store:false`, 도구 없음, Structured Outputs. API 키는 실행 프로세스 메모리에만 사용했다.
- 최종 프롬프트: `src/lib/reading-prompt.ts`, 버전 `otaku-report-v1.5`.
- 5개 합성 입력 fixture를 정의했으나 이번 반복 생성 비교에는 0~3의 4개만 사용했다. 윤달 fixture는 라이브러리 단위 검증에 포함했으며 실제 AI 생성 테스트에는 사용하지 않았다.

## 결과

| 단계 | 호출 수 | 변경 | 결과 |
| --- | ---: | --- | --- |
| v1.1 baseline | 4 | 초기 장문 지침 | 본문 377~521자, 호칭 누락, 제목 미준수 |
| v1.2 tuned | 2 | 문단 250~260자 JSON Schema 제한, 호칭 횟수 명시 | 분량은 근접했지만 잘린 문장·반복 기니·이모지 발생. 폐기 |
| v1.3 refined | 2 | 강제 문자열 길이 제한 제거, 문체 예시와 완결성 강조 | 본문 553~648자. 완결성은 개선됐지만 분량 부족 |
| v1.4 final | 2 | medium reasoning, high verbosity, 상세 전개 지침 | 본문 781~919자. 분량 초과, 일부 제목 오류 |
| v1.5 repair | 2 | 실제 검사 오류와 초안을 제공한 1회 보정 | 한 사례는 8장 중 7장 700~750자 통과, 2번 687자. 다른 사례는 806~882자로 여전히 초과 |

**전체 8개 장이 모든 검사를 통과한 보고서: 0건.** 프롬프트와 보정 절차를 개선했지만 아직 정확한 분량을 안정적으로 맞추지 못한다. 공개 AI 보고서 기능은 기본 비활성으로 유지한다. API 경로는 오류 결과를 완성본으로 노출하지 않고 계산 결과를 유지한다.

검사 항목: JSON 구조, 장 순서, 제목 35~45자/쉼표/기니 1회, 본문 3문단/700~750자, 호칭, 한자·이모지, 시기 근거, 근거 id, 완결 문장, 깨진 자리표시자, 데이터 범위 안내. 초기 검사에서 ‘그대로’를 ‘그대’로 잘못 감지하는 오탐을 발견해 단어 단위로 수정했다. 최종 보정 결과에는 수정된 검사기를 사용했다.

근거 id 유효성은 의미적 정확성의 증명이 아니다. 수동으로 확인한 예시에서 고정된 짧은 근거 사전 때문에 서술이 일반적인 감상·기록·휴식 조언으로 반복되는 경향도 남아 있다. 더 자세한 사주 해석을 판매하려면 검수된 근거 사전을 보강해야 한다. 두 라이브러리의 일치도 독립적인 KASI 전체 검증을 대체하지 않는다.

## 사용량

- 입력 토큰: 41,783 (캐시 읽기 11,934, 캐시 쓰기 29,813 포함)
- 출력 토큰: 47,498 (추론 2,204 포함)
- 개별 호출 소요: 약 27~72초
- 공식 Luna 기본 요율 및 캐시 쓰기 가산 반영 계산: 약 **USD 0.0647**. 실제 청구액은 플랫폼 사용 내역이 기준이다.

공식 요율: https://developers.openai.com/api/docs/models/gpt-5.6-luna

## 재현

```bash
# OPENAI_API_KEY는 안전한 실행 환경으로 제공한다.
node --import tsx scripts/eval-reading.ts 0 4 baseline
# 프롬프트를 조정한 뒤 같은 fixture로 비교
node --import tsx scripts/eval-reading.ts 0 2 final
node --import tsx scripts/eval-repair.ts
```

원본 실행 결과는 로컬 `.eval/`에만 있다. 이 폴더는 Git에서 제외한다. 대표 초안은 [luna-sample-draft.md](./luna-sample-draft.md)에 보관했다. 프롬프트 버전은 결과에 기록하지만 모델 응답 자체의 재현성은 보장하지 않는다.

## 코드 검증

- 엔진/교차검증 테스트 10개, 입력·출력 계약 테스트 5개 통과.
- TypeScript, ESLint, Next.js production Webpack 빌드 통과.
- 현재 환경의 Turbopack 내부 포트 생성 오류로 지원되는 Webpack 빌드를 사용하도록 설정했다.
- 로컬 화면에서 합성 입력 → 3주 명식 → 5축 점수와 근거 표시 확인.

## 남은 제품 결정

1. 본문 700~750자가 절대 조건이라면 문단별 생성/수정 또는 검수된 템플릿과 조합하는 방식을 별도로 평가한다. 무제한 재시도나 임의의 글자 자르기는 하지 않는다.
2. 정밀 글자 수보다 글의 자연스러움이 우선이면 허용 범위를 제품에서 명시적으로 바꾼 뒤 테스트한다. 이번 작업에서는 통과 기준을 완화하지 않았다.
3. 공개 활성화 전 새 API 키를 Vercel 서버 환경변수에 설정하고 분산 호출 제한과 비용 통제를 갖춘다. 테스트에 제공된 키는 대화에 노출되었으므로 교체를 권한다.
