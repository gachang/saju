# 실제 완성 보고서 평가 · 2026-09-12

## 확실히 확인한 결과

[완성 보고서](../reports/complete-example.md)는 실제 OpenAI API 출력이며 수작업으로 본문을 잘라내거나 문장을 채운 결과가 아니다. Luna 초안에 장별 보정과 Terra low 편집 검수를 적용했다. 최종 결과는 8장, 장당 3문단, 본문 글자 수 `725 / 725 / 716 / 731 / 726 / 726 / 726 / 715`(총 5,790자)다. 제목은 35~42자다.

서버에서 재계산한 근거·점수·유형과 비교하고 모든 장을 별도로 읽어 검토했다. 관계의 차이를 닮음으로 바꾼 해석과 입력에 없는 월주의 의미를 추가한 부분은 다시 생성해 수정했다. 최종 자동 검증 오류는 0개, 마지막 Terra low 검수 이슈도 0개다. 이는 문학적 품질 또는 사주 해석의 정확성을 절대적으로 보증하지 않는다.

이 예시는 여러 평가 체크포인트에서 재개해 완성한 결과다. 마지막 실행의 32.083초·3호출은 신규 보고서 한 편의 전체 생성 시간·비용이 아니다. 실제 고객 생일·이름을 사용하지 않았고 API 키는 파일·Git·Vercel에 저장하지 않았다.

## 관찰한 실패와 수정

| 실제 평가 | 관찰 | 적용한 수정 |
| --- | --- | --- |
| Luna v2 초안 2건 | 짧은 제목, 본문 분량, 격식체 오류 | 검증 실패 장만 재작성, 실측 길이와 수정할 문단 전달 |
| 장별 보정 | 8장 분량 통과 후 장간 동일 문장 발견 | 긴 동일 문장 탐지 및 충돌 문장 전달 |
| 별도 내용 검수 | 월주에 제공되지 않은 의미 추가, 차이를 닮음으로 해석 | 근거 의미·위치 검수, Terra low 국소 수정·재검수 |
| Terra low 전체 초안 비교 | 전체 모델을 올려도 짧은 제목과 본문이 남음 | 전체 고급 모델 전환보다 Luna 초안+선택 보정 유지 |
| v2.1 신규 전체 생성 | Luna medium 보정의 출력 2,200토큰을 추론이 소진해 미완성 | 단문 보정 low/2,800토큰, 해당 장만 다음 단계로 이관 |
| v2.1 신규 재시험 | 쉼표 뒤 어미만 남은 제목, 보정 누적으로 429 | 긍정 제목 예시, v2.2 생성용 제목 min/max 제약 |
| v2.2 패턴 제약 포함 신규 생성 | `incomplete/max_output_tokens`, 사용량 0, 출력 없음 | 확인되지 않은 API 패턴 제약은 제거; 진단 상태·미완성 사용량 추적 추가 |
| 최소 출력 스키마 비교 | 일반 문자열과 min/max 문자열은 각각 200; 패턴 확인은 429 | 검증된 min/max만 API에 적용하고 어미는 서버 검증 유지 |

최종 신규 전체 검증은 완료하지 못했다. 마지막 Luna 진단에서 요청 한도 `50`, 사용 `50`, 잔여 `0`, 요청 재설정 헤더 `23h57m44.204s`를 관찰했다. `Retry-After`는 별도 값으로 반환되므로 재시도 가능 시점을 단정하지 않는다. 추가 Luna 호출은 중단했다. v2.2 전체 실행은 한도 회복 또는 사용 가능한 프로젝트 한도 확보 후 다시 확인해야 한다. 기존 완성본의 성공과 최종 신규 생성 성공을 구분한다.

여러 실패를 포함해 실제 API 호출은 10회를 넘었다. API 호출 하나와 전체 보고서 테스트 한 건은 다르며, 10개 입력이 전부 완성됐다고 해석하면 안 된다. 초기 실패 실행 일부의 사용량 추적이 없으므로 전체 실험의 정확한 호출 수·총비용은 산출하지 않았다. 기록된 사용량은 `.eval/`의 로컬 평가 파일에 남겼으며 Git에는 넣지 않는다.

## 모델과 운영 설정

최종 구현은 Luna low 초안 → 코드 검사 → 실패 장 Luna low → 필요한 장만 Terra low(최대 2단계) → Terra low 내용 검수다. 기존 완성 예시의 초안은 Luna medium이었으며, 낮춘 신규 전체 설정은 위 한도로 아직 끝까지 확인하지 못했다. 검수에 문제가 있으면 최대 2회 국소 수정 후 재검수하고, 마지막 검사에서도 문제가 남으면 완성본을 반환하지 않는다. [Luna 공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-5.6-luna), [Terra 공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-5.6-terra).

제목 길이는 프롬프트만이 아니라 [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)의 문자열 min/max로 제약한다. 공식 문서상 패턴도 지원하지만 이번 호출에서 충분히 검증하지 못했으므로 API에 전달하지 않는다. 실제 표시 글자 수·제목 어미·근거 인용·중복·안전 범위는 서버에서 다시 검사한다. 형식 제약만으로 올바른 의미가 보장되지는 않아 별도 검수를 유지한다.

이번 계정 응답에서 토큰 한도 10,000 및 요청 한도 50 헤더를 관찰했다. 남은 요청의 재설정 시간은 수 시간이므로 이를 단순히 '분당 50회'로 설명하지 않는다. `rate_limit_exceeded`만 제한적으로 재시도하며 `Retry-After`뿐 아니라 토큰 재설정 헤더도 반영한다. 잔액 부족·인증 실패·장시간 요청 한도는 반복 호출하지 않는다. 출력 예약량과 입력 합계 때문에 짧은 확인 요청이 성공해도 긴 보고서 요청은 429일 수 있다.

전체 220초 제한, 장 보정 동시 실행 2개, 취소 전파, 성공 장 보존, 제한 횟수 이후 실패 반환을 적용했다. 여러 인스턴스에 걸친 분산 제한·인증·결제·작업 큐는 아직 구현하지 않았다. 공개 AI 기능은 기본 비활성이며 키의 서버 등록과 비용 제어를 갖춘 공개 활성화는 별도 작업이다.

## 남은 검증 범위

마지막 코드 검증은 76개 테스트(계산 10, 보고서 19, 보정 파이프라인 24, 재시도 9, 출력 스키마 13, 실제 완성본 회귀 1), TypeScript, ESLint 및 Next.js 프로덕션 빌드를 포함한다. 이는 실 API 신규 보고서 76건을 뜻하지 않는다.

완성 예시는 합성 입력 한 쌍이다. 다른 오행 관계, 윤달·절기·자정 경계, 가능한 명식이 여러 개인 입력, 1자/12자 호칭에 대한 더 넓은 실 API 성공률·지연·비용 측정이 필요하다. 호칭 길이 및 경계 입력의 코드 회귀 테스트가 실제 모델의 모든 출력에 대한 성공률을 뜻하지는 않는다. 전체 명리 체계나 연도별 운세를 추가하지 않았으며 현재 규칙 엔진의 범위를 넘겨 해석하지 않는다.
